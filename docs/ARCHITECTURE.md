# Architecture

## Scope

Three WSO2 Identity Server 7.3.0 journeys use a shared voice-delivery core:

1. OIDC MFA — voice OTP as the second factor.
2. Passwordless — OTP authentication without a password.
3. Password recovery — voice delivery inside WSO2's recovery flow.

## System design

```text
WSO2 IS 7.3.0 (Java 21 / OSGi)
  +-- MFA Authenticator
  |     WSO2 AbstractOTPAuthenticator
  +-- Passwordless Authenticator
  |     AbstractOTPAuthenticator + PasswordlessOTPAuthenticator
  +-- Recovery Executor
  |     WSO2 AbstractOTPExecutor
  +-- Voice OTP Core
  |     delivery orchestration, correlation, idempotency,
  |     timeout/reconciliation, channel and fallback policy
  +-- Asterisk ARI Client
  |     REST + WebSocket events
  +-- WSO2 SMS fallback integration
          reuses existing local SMS notification event/provider

WSO2 -- secured ARI --> Asterisk call --> Stasis/Dialplan --> SayDigits(OTP)
```

## OTP ownership

WSO2 remains authoritative for OTP generation, validation, storage, expiry, retry/resend limits, and recovery-token lifecycle. This repository must not create a parallel OTP engine.

- MFA and Passwordless use OTP authenticator extension points shipped in IS 7.3.0.
- Passwordless additionally implements WSO2's PasswordlessOTPAuthenticator contract.
- Recovery integrates through the supported Flow Execution / recovery executor extension point.
- Delivery receives the OTP generated by WSO2 and reports delivery state only.
- Dependency versions must match those shipped in IS 7.3.0, not arbitrary latest upstream versions.

## Asterisk voice: ARI + SayDigits

WSO2 connects directly to Asterisk ARI; no separate middleware service is planned.

1. WSO2 creates an opaque, non-sensitive delivery correlation ID.
2. WSO2 originates the call through ARI.
3. Asterisk enters the configured Stasis application and controlled Dialplan.
4. Dialplan sets channel language and invokes `SayDigits()`.
5. Completion/failure is correlated with WSO2 delivery state.
6. Sensitive channel variables and delivery resources are cleared when safe.

### SayDigits is not TTS

`SayDigits()` plays prerecorded digit prompts based on Asterisk channel language. No TTS engine is included.

- English requires corresponding sound prompts installed.
- Persian requires a tested Persian digit prompt set installed and configured. Asterisk 20+ alone does not guarantee Persian audio.
- OTPs remain strings; leading zeroes must be preserved.
- Issabel TTS, Piper, ElevenLabs, external TTS, and alternative speech engines are out of scope.

ARI/Stasis/Dialplan handoff and reliable playback-completion signaling require integration tests before production use.

## SMS fallback

Voice is primary; SMS is fallback under a configurable policy.

- SMS must carry the **same OTP**; never start a second challenge.
- Reuse WSO2 IS 7.3.0's `TRIGGER_SMS_NOTIFICATION_LOCAL` event and configured SMS sender/provider wherever supported.
- Do not implement a new SMS provider unless compatibility tests prove the existing extension point insufficient.
- Definitive failures (busy, no answer, call/playback failure) may trigger fallback.
- Ambiguous call state must be reconciled first to avoid duplicate SMS.
- Successful voice playback must not trigger SMS.

## Security invariants

- OTP never appears in URLs, ARI `appArgs`, logs, exception messages, metric labels, or trace attributes.
- Correlation IDs are opaque and do not encode OTP or phone number.
- Destination comes from a trusted WSO2 user claim and is validated before dialing.
- ARI credentials use secure configuration/secrets; never source control.
- ARI is protected by TLS, network restrictions, and least-privilege account.
- Apply rate limits, attempt/resend limits, short-lived state, and idempotency.
- Redact phone numbers in diagnostic logs.
- Handle late, duplicate, missing, and out-of-order ARI events.
- Preserve OTP as a digit string; clear sensitive channel variables as soon as safely possible.

## Configuration concepts (not a finalized syntax)

- Enablement per journey
- ARI endpoint, credentials, TLS trust, Stasis application
- Call/event/reconciliation timeouts and concurrency limits
- Trusted mobile claim
- Default/per-request language and prompt availability
- Voice primary / SMS fallback policy
- Retry, rate-limit, and delivery policy

Final names and syntax must be validated against WSO2 IS 7.3.0 Configuration Framework.

## Testing and acceptance

**Unit:** digit strings/leading zeroes, state machine, correlation, idempotency, timeout, fallback, language, configuration validation, log redaction.

**Integration:** ARI auth/originate/Stasis/Dialplan; SayDigits in English and Persian prompt set; completion, busy, no answer, hangup, ARI outage/reconnect/ambiguous events; WSO2 MFA, Passwordless, Recovery; same-OTP SMS fallback.

**Runtime/packaging:** Java 21 Maven build; OSGi resolution and activation on IS 7.3.0; feature packaging/install/restart/upgrade/rollback; target 30 concurrent calls; replay, leakage, throttling, duplicate-delivery tests.

No component is production-ready until tests run against target WSO2/Asterisk.

## Phases

1. Compatibility baseline (WSO2 7.3.0 extension points, ARI/SayDigits behavior).
2. Maven/OSGi scaffolding, version management, bundle metadata, feature packaging.
3. Voice OTP Core.
4. ARI client, WebSocket events, call lifecycle, Dialplan handoff.
5. SayDigits and language/prompt assets.
6. SMS fallback using existing WSO2 event/provider and same OTP.
7. MFA authenticator.
8. Passwordless authenticator.
9. Password recovery executor.
10. End-to-end, security, concurrency, packaging and operations.
